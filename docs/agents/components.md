# Shared components (`kubernetes/components/`) — agent topic guide

Part of the `AGENTS.md` topic guides (`docs/agents/`). Read when adding or changing apps that
consume `kubernetes/components/*`, or when changing a component itself.

Inventory (all included at the namespace layer, not from `flux-system`, to keep namespace
encapsulation):

| Component              | What it provides                                                                                                                                                                                                                                                                                                                         |
| ---------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `alerts`               | Shared PrometheusRule/alerts resources (included by every namespace `kustomization.yaml`).                                                                                                                                                                                                                                               |
| `app-template`         | The common `app-template` `OCIRepository` pinned cluster-wide (currently `5.3.0`), included by the 7 consuming namespaces (`ai`, `media`, `network`, `niks3`, `observability`, `selfhosted`, `volsync-system`). Renovate's flux manager tracks all 7 generated documents in `kubernetes/components/app-template/ocirepository.yaml`.     |
| `authentik`            | Standard `SecurityPolicy` extAuth targeting `${APP}-${DOMAIN_SLUG:=480p-com}` with `failOpen: false`; nested envsubst defaults (`${A:=${B:=x}}`) are supported by Flux and flate. Non-standard/multi-route workloads (echo, grafana, prometheus, alertmanager, victoria-logs, vaultwarden-admin, kopia) keep dedicated SecurityPolicies. |

Its `pgdump.yaml` is an **unreferenced dead template** — see `docs/agents/backups.md`.                                                       |

| `dragonfly`            | Per-app Dragonfly (Redis-compatible) cache — see below.                                                                                                                                                                                                                                                                                  |
| `gateway-route-access` | Shared route/gateway access resources.                                                                                                                                                                                                                                                                                                   |
| `kopiur`               | Backup PVC + `Restore` populator + `SnapshotPolicy` — see `docs/agents/backups.md` for the substitutes and traps.                                                                                                                                                                                                                        |

If used: its PVC template names the claim `${APP}` and ignores `VOLSYNC_CLAIM`.                                                                                                                         |

## dragonfly component specifics

- Snapshots each cache to a per-app PVC every 5 minutes (`spec.snapshot.cron` + the component's `snapshot-pvc.yaml`, operator v1.6.1+) with a **fixed** `--dbfilename=dump` so each snapshot overwrites the last and usage stays flat at ~dataset size (128Mi default). Never override `DRAGONFLY_SNAPSHOT_DBFILENAME` with a kopia-style `{timestamp}` macro — dragonfly never prunes old sets and the PVC fills at 288 sets/day on the default cron.
- The CR references the PVC via **`existingPersistentVolumeClaimName`**, NOT `persistentVolumeClaimSpec`: the latter appends a `volumeClaimTemplate` to the operator's StatefulSet, and claim templates are immutable — adding snapshots to an existing Dragonfly errors with `VolumeClaimTemplates change detected but cannot be applied` + a stray `volumeMounts[0].name: Not found: "df"` and needs instance delete/recreate. An existing-PVC reference is a plain pod volume: rolls in place, and the PVC stays independently resizable.
- The component's CiliumNetworkPolicy must also allow the operator on the admin port 9999 (`ns dbms` + `app.kubernetes.io/name: dragonfly-operator`; `resources.DragonflyAdminPort`) — a **second** ingress rule; the operator needs nothing on 6379, so the data-port `ingressDeny` keeps naming only the app's own labels.
- Operator v1.7+ decides dataset-loaded/master by reading `INFO persistence` from the **pod IP on 9999**, and the `role: master` label it then sets is what the generated Service selects on: a pod without that label leaves the Service with **no endpoints**, so its ClusterIP silently drops (i/o timeout in the app, not connection refused) while the instance itself is Running and listening. Diagnose with `kubectl -n <ns> get endpoints <app>-dragonfly` (empty = this) and `kubectl -n dbms logs deploy/dragonfly-operator -c manager | grep "dataset load status"`. An instance that never got the label must be **deleted** (or the operator restarted) to re-trigger the pod lifecycle reconcile — annotating the `Dragonfly` CR only re-runs the instance controller, which does not set the label.

## Common app-template default to remember

- app-template v5 defaults `defaultPodOptions.automountServiceAccountToken` to `false`; apps/sidecars that call the Kubernetes API (Gatus sidecar, Homepage discovery) must explicitly set it to `true` or mount a projected token.
